# Usage

This document collects the usual commands for training, TensorBoard, and Rerun.
Run all commands from the repository root.

## Setup

Install the project and development dependencies:

```bash
uv sync
```

Install the optional Rerun dependency when creating or opening `.rrd` recordings:

```bash
uv sync --extra visualization
```

## Starting training

The default training configuration is
`configs/ppo_hover_baseline.toml`. Start a CPU run with:

```bash
uv run python scripts/train.py \
  --config configs/ppo_hover_baseline.toml \
  --device cpu
```

For a CUDA-enabled PyTorch installation, use:

```bash
uv run python scripts/train.py \
  --config configs/ppo_hover_baseline.toml \
  --device cuda
```

The script prints the paths of the created run directory, metrics CSV,
TensorBoard directory, and evaluation directory. A run is stored as:

```text
runs/<experiment>/<run_id>/
```

The run directory contains a frozen `config.toml`, `metadata.json`,
`metrics.csv`, `tensorboard/`, `checkpoints/`, `plots/`, and `evaluation/`.

Change the number of updates and other experiment parameters in the TOML file
before starting a run. The copied configuration inside the run directory is the
configuration used by that run.

## Recording a training evaluation

Training always saves deterministic evaluation trajectories as `.npz` files at
the configured evaluation interval. To additionally save a Rerun `.rrd` file
for every evaluated episode, set this field in the configuration:

```toml
[tracking]
record_evaluation_rerun = true
rerun_step_stride = 10
```

The evaluation frequency and number of episodes are configured separately:

```toml
[evaluation]
interval_updates = 10
episodes = 2
```

Then start training with the visualization extra available:

```bash
uv run --extra visualization python scripts/train.py \
  --config configs/ppo_hover_baseline.toml \
  --device cuda
```

Evaluation recordings are written under:

```text
runs/<experiment>/<run_id>/evaluation/
update_000010_episode_001.npz
update_000010_episode_001.rrd
```

The `.rrd` file contains the deterministic evaluation trajectory, target,
vehicle pose, body/motor geometry, and motor-thrust timelines. It is not a
recording of every exploratory training rollout; it is a periodic snapshot of
the deterministic evaluation policy.

For an existing run whose `record_evaluation_rerun` was disabled, the `.npz`
trajectory can still be converted to `.rrd` later with the project’s
`Trajectory` and `log_trajectory` APIs. The final evaluation recordings for
run `20260831_031226_seed42_4c8d9562` are already present in that run’s
`evaluation/` directory.

## TensorBoard

Start TensorBoard in a separate terminal. It can read a run while training is
still running; keep the process active and refresh the browser as needed.

Open all runs of one experiment:

```bash
uv run tensorboard \
  --logdir runs/ppo_hover_baseline \
  --port 6006 \
  --reload_interval 1
```

Open all experiments under `runs/`:

```bash
uv run tensorboard \
  --logdir runs \
  --port 6006 \
  --reload_interval 1
```

Open one specific run:

```bash
uv run tensorboard \
  --logdir runs/ppo_hover_baseline/<run_id>/tensorboard \
  --port 6006 \
  --reload_interval 1
```

The same commands work for live and completed runs. Open
`http://localhost:6006` in a browser. If port `6006` is already in use, choose
another port, for example `--port 6007`.

Useful current-run example:

```bash
uv run tensorboard \
  --logdir runs/ppo_hover_baseline/20260831_031226_seed42_4c8d9562/tensorboard \
  --port 6006 \
  --reload_interval 1
```

## Opening recordings

Open a physics-diagnostic Rerun recording saved by
`diagnose_physics.py`:

```bash
uv run --extra visualization rerun \
  artifacts/physics_diagnostics/tilted_thrust_rk4.rrd
```

Open a training evaluation recording:

```bash
uv run --extra visualization rerun \
  runs/ppo_hover_baseline/<run_id>/evaluation/update_001000_episode_001.rrd
```

For the current completed run, for example:

```bash
uv run --extra visualization rerun \
  runs/ppo_hover_baseline/20260831_031226_seed42_4c8d9562/evaluation/update_001000_episode_001.rrd
```

The current run also has a useful earlier comparison at update 410:

```bash
uv run --extra visualization rerun \
  runs/ppo_hover_baseline/20260831_031226_seed42_4c8d9562/evaluation/update_000410_episode_001.rrd
```

To generate a physics recording and open its viewer immediately:

```bash
uv run --extra visualization python scripts/diagnose_physics.py \
  --scenario tilted_thrust \
  --integrator rk4 \
  --duration 2.0 \
  --dt 0.01 \
  --rerun \
  --spawn \
  --output-dir artifacts/physics_diagnostics
```

`--spawn` is for a recording being generated by the diagnostic script. For a
previously saved `.rrd`, use the standalone `rerun <path>` command above.

## Recording predefined hover scenarios

Use the trained actor from an existing run to evaluate deterministic initial
states designed to isolate position recovery. The scenarios are defined in
`src/environments/quadrotor/hover_scenario.py`:

```text
at_target   -> target position, target attitude, zero velocity and rates
near_target -> 0.25 m along world +X, target attitude, zero velocity and rates
far_target  -> 2.0 m along world +X, target attitude, zero velocity and rates
```

Create `.npz` and `.rrd` recordings for all scenarios with a run ID:

```bash
uv run --extra visualization python scripts/record_hover_scenarios.py \
  20260831_031226_seed42_4c8d9562
```

The script searches below `runs/`, loads the run’s frozen configuration and
final checkpoint, and writes recordings to:

```text
runs/<experiment>/<run_id>/evaluation/hover_scenarios/
at_target.npz   at_target.rrd
near_target.npz near_target.rrd
far_target.npz  far_target.rrd
```

Use the best evaluation checkpoint instead of the final checkpoint when useful:

```bash
uv run --extra visualization python scripts/record_hover_scenarios.py \
  20260831_031226_seed42_4c8d9562 \
  --checkpoint best
```

Open a generated scenario recording with:

```bash
uv run --extra visualization rerun \
  runs/ppo_hover_baseline/<run_id>/evaluation/hover_scenarios/far_target.rrd
```
